# UCAPSA Product Discovery System

**Fecha de inicio:** 27 de septiembre de 2026  
**Marco principal:** April Dunford + Teresa Torres

Este directorio convierte la investigación de producto en un proceso repetible. Su objetivo no es recopilar opiniones generales sobre la app, sino producir evidencia que permita distinguir entre:

- problema de posicionamiento;
- problema de relevancia del valor;
- problema de comprensión;
- problema de confianza;
- problema de UX;
- problema de recurrencia;
- problema de hábito/comportamiento;
- problema de segmento.

## Secuencia de trabajo

1. **Dunford — alternativa actual**
   - ¿Qué hace hoy la persona cuando UCAPSA App no existe?
   - ¿Qué herramientas, personas o atajos usa?
   - ¿Qué capacidad diferente ofrece UCAPSA?
   - ¿Qué valor produce esa diferencia?

2. **Torres — outcome y oportunidades**
   - Mantener un outcome de producto claro.
   - Entrevistar sobre historias reales, no opiniones hipotéticas.
   - Convertir necesidades/dolores/deseos observados en oportunidades.
   - Añadir al Opportunity Solution Tree sólo oportunidades respaldadas por evidencia.
   - Probar soluciones y sus supuestos por separado.

3. **Prueba de comprensión**
   - Mostrar Home 10–15 segundos sin explicación.
   - Retirar la pantalla.
   - Pedir a la persona que explique para qué sirve y qué le resolvería.

4. **Prueba de tareas**
   - Pedir tareas reales sin indicar dónde tocar.
   - Registrar si puede resolverlas, cuánto tarda y dónde duda.

5. **Seguimiento**
   - Comparar lo que la persona dijo con lo que hace después.
   - No interpretar correlación como causalidad.

## Regla de evidencia

Una observación individual puede generar una **hipótesis**, pero no se convierte automáticamente en una oportunidad del árbol.

Para añadir una oportunidad al OST se necesita al menos una de estas condiciones:

- el mismo patrón aparece en **2 o más historias independientes**; o
- el patrón aparece una vez pero bloquea una tarea crítica y puede reproducirse directamente; o
- existe evidencia cuantitativa consistente que apoya el mismo problema.

Cada oportunidad debe enlazar a los IDs de entrevistas que la respaldan.

## Primera ronda

Muestra inicial de descubrimiento:

- INT-001 — Propietario / operación.
- INT-002 — Admin o instructor.
- INT-003 — Cliente Puppy.
- INT-004 — Cliente Puppy.
- INT-005 — Cliente Comandos Básico.
- INT-006 — Cliente Comandos Intermedio/Avanzado.
- INT-007 — Socio.
- INT-008 — Cliente con disminución o abandono reciente.

No se usa esta muestra para estimar porcentajes poblacionales. Se usa para encontrar patrones y oportunidades.
